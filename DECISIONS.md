# Decisions

Decision Entries. Read before proposing changes to a covered area.

- [D-20260919-001] The compaction mechanism is the Remote Control bridge (`POST /v1/code/sessions/{bridgeSessionId}/events`), called directly — not browser/UI automation. — Route 2 was chosen over UI automation (option 1, ruled out) and proven callable without a browser. (status: active)
- [D-20260919-002] A bridge event MUST carry `anthropic-client-platform` of a human value (`web_claude_ai`); `cli` is demoted to a peer message and slash commands do not execute. — This is the single verified discriminator that makes `/compact` run as user input. (status: active)
- [D-20260919-003] The event envelope keeps a top-level `event_type` alongside the nested `payload` (with `payload.type`). — A flat body returns HTTP 400 "event_type is required"; do not flatten it. (status: active)
- [D-20260919-004] `/compact` command text is constructed in-process (never passed as a shell argument). — Git Bash MSYS path-conversion rewrites a leading-slash argument into a Windows path; constructing internally also keeps intent separate from execution. (status: active)
- [D-20260919-005] The "self" target is bound only from the runtime — per-process session records cross-checked against `CLAUDE_CODE_HOST_SESSION_ID`/`CLAUDE_CODE_SESSION_ID`/`CLAUDE_PID` and the Stop-hook stdin session id — requiring ≥2 corroborating identifiers when available, never a model-supplied bridge id. — Prevents firing a state-changing command at the wrong or an attacker-named session. (status: active)
- [D-20260919-006] Intent and execution are separate: the agent records a compaction request at verified scope closure; a Stop hook consumes it exactly once (request file deleted before firing) and executes `/compact` after the final answer. — Guarantees single-fire idempotency and end-of-turn ordering. (status: active)
- [D-20260919-007] The OAuth token is refreshed only when within the expiry margin, mirroring the CLI's endpoint/client-id/rotation, and the rotated credentials are written back atomically. — During an active closure the token is almost always valid, so refresh (and refresh-token rotation) stays rare, minimising desync with the Desktop app's in-process auth. (status: active)
- [D-20260919-008] The allowlisted CLI (`tools/bridge_send.py`) acts only on the runtime-bound current session (`--self`) and only ever sends a constructed `/compact`; there is no free-text sending, and explicit selectors are inspection-only (`--dry-run`). — The Bash allow rule makes it promptless, so any wider capability is promptless cross-session "human" input. (status: active)
- [D-20260919-009] conPACT's own state (compaction requests, hook log) lives under `~/.claude/conpact/`, never inside Claude Code's runtime folder `~/.claude/sessions/`. — That folder is Claude Code's registry of live processes; foreign files there were read back as session records and may be tidied away. (status: active; its location superseded by D-20260923-048 - the state now lives in `~/.conpact/`, still never inside `~/.claude/sessions/`)
- [D-20260919-010] A claimed compaction request fires at most once and fails closed: only the hook whose delete of the request succeeds may send, and a refused or failed send is reported and logged, never retried or re-armed. — Makes D-20260919-006's single-fire guarantee hold under locks and races; a retry path could compact a session repeatedly. (status: active)
- [D-20260919-011] A minimum context size is a one-shot condition on a closure request: the Stop hook that claims the request measures the context from the transcript once, fires only if it is at least the minimum, and otherwise discards the request (and fails closed when the size cannot be measured). It is never kept armed waiting for the context to grow. — The brief rules out threshold-triggered compaction; the condition only decides whether a closure compaction is worth doing. (status: active)
- [D-20260919-012] The MCP server only queues, cancels and inspects requests for the session that started it; it takes no target argument, binds via its OS parent pid's session record corroborated by `CLAUDE_CODE_SESSION_ID`, refuses stale or foreign identities, and never sends to the bridge or reads the token — execution stays with the Stop hook. — Keeps D-005/D-008's self-only binding and D-006's intent/execution split for the tool-call path. (status: active)
- [D-20260919-013] The idle notifier is a separate feature (requested by the maintainer on 2026-09-19), not a change to closure requests (D-006/D-011 stand): at each turn end of a session whose context is ≥ `min_context_tokens` (default 100k) the Stop hook starts one detached watcher per watch generation, which acts `lead_seconds` (default 300) before the prompt cache expires — the TTL read per session from the transcript's cache-write breakdown (1 h → 55 min idle, 5 min → 3 min), never earlier than 60% of the TTL — and only if the session is still idle and bound; an unknown TTL arms nothing. It sends only a constructed `/compact`, only to the runtime-bound session (D-005), never while the session is busy (a busy session receives it as text), at most once per watch. — the maintainer's sessions all use the 1-hour cache (every cache write in the 25 latest transcripts), so a fixed 3-minute delay would have compacted ~57 minutes early; he chose "just before expiry". (status: active)
- [D-20260919-014] Auto-compact is per session and is switched on only by the user's click on that session's toast ("Auto-compact this session") and off by the notice's button; no agent-facing surface (CLI, MCP tools) can read or set it. — the maintainer chose per-session scope; keeping the switch off the promptless CLI and the MCP tools stops an agent from turning its own sessions into silent auto-compaction (D-008's reasoning). (status: active)
- [D-20260919-015] The toast is a stdlib Tk window handled inside the watcher process: mouse-only label buttons, shown without taking focus (no-activate tool window, foreground handed back), bottom-right of the work area. No native WinRT toast, URI protocol handler, COM activator, registry entry or third-party package. — Native toast buttons need a registered protocol or COM activation — persistent system configuration and a new attack surface for a command that compacts a live session; Tk ships with Python and keeps the click in-process. (status: active; its mechanism amended by D-20260924-054, which refuses activation from before Tk makes its first window and hands the keyboard back at once)
- [D-20260919-016] The user's settings live in `~/.claude/conpact/settings.json`, holding only changed values, except the idle toast's on/off, which stays the off-switch file `idle-notify.off` that the Stop wrapper checks before starting Python. They change only through the settings window (a toast's Settings link starts it as its own process) or `tools/settings.py`. Every value is range-checked, and a save is all or nothing. `closure_min_context_tokens` applies when a claimed request has no minimum of its own; otherwise D-011 is unchanged. Neither the MCP tools nor the allowlisted CLI read or write settings, and the per-session auto-compact switch is not a setting (D-014 stands). — the maintainer asked on 2026-09-19 for every setting, including the minimums, to be configurable through a window and a command. Keeping the switch a file keeps a turn end free of Python when the toast is off. (status: active)
- [D-20260919-017] The idle notifier's watch has stages: an early toast at `idle_seconds` (when the user sets one) and the last one `lead_seconds` before the prompt cache expires; both come, and only a compaction, a silence or the session being used again stops the later one. Each session's auto-compact switch names the stage it acts at (`early` or `expiry`), set only by the toast's auto button at the stage it was pressed; the other stage then stays silent. "Silence this session" writes a per-session mute (`mute_seconds`, default 24 h) that also ends as soon as the session is used again. A session the user has archived in the desktop app is never toasted or compacted: `app_sessions` reads the app's own session store (`archived-sessions.idx` and each record's `isArchived`) at the turn end and again at the notify time, read-only, and an unreadable store reads as "not archived". — the maintainer asked on 2026-09-19 for both timings to work at once, for a dismissed idle toast not to cancel the expiry one, for a per-session silence, for archived sessions to be left alone, and to set and forget which stage a session auto-compacts at. Archiving does not stop a session (measured in the app's log), so the runtime record alone cannot tell; failing open keeps a parse failure from silencing a live session. This amends D-013 (idle_seconds replaced the pre-expiry timing) and extends D-014 (the switch is still per session and still off every agent surface). (status: active)

Assertions never go inside a `present()` callback. — The watcher deliberately swallows whatever a presenter raises, so that a broken toast can never crash it; that also swallowed six test assertions and every guard that fired inside one. The three requirements also reach a session by different routes, and only the hook arrives without help: the Stop hook is read from `~/.claude/settings.json` at every turn end, an MCP server is a child process started only when the session's own process starts, and Remote Control is a per-session switch that is what puts `bridgeSessionId` in the record. - [D-20260920-021] conPACT writes exactly one key in Claude Code's own user settings - `remoteControlAtStartup` in `~/.claude/settings.json` - and only when the user clicks "Always on for new sessions" on the Remote Control toast. - [D-20260920-022] An agent can hold its *own* session's early idle toast, through the MCP tool `hold_idle_toast` (minutes, at most 120; 0 releases it): a long run is idle without being finished, and between builds and test suites the early toast would offer to compact a session that is about to be used again. - [D-20260920-025] A mutation run's "timeout" is an unfinished measurement, never a detection. `tools/mutate.py` re-runs a timed-out mutant against its own module's tests at a 300-second limit, counts only `killed` towards a score, and lists any timeout that still does not settle alongside the survivors, so it has to be looked at. One of the eight silently disabled `python -m conpact.settings_window`; the same gap sat in `idle_watch`, where it had been written off as "uncovered by design". Found by a parallel session re-checking a single mutant, not by review. This corrects the evidence recorded under D-20260920-024 and in CU-20260920-026. (status: active)
- [D-20260921-026] The early idle toast can hand its compaction to the stage before the cache expires, and the two ways of saying so are deliberately different in lifetime. "Near expiry" is one-shot and is held only in the watcher process - nothing is written to disk - so using the session ends the watcher and the deferral with it and the next Stop arms a fresh watch; "Always near expiry" writes the existing per-session auto switch, which is what makes it outlive the watch. Both are offered only on the early stage, which is the only one with a later stage to hand the work to. A notice shown after a one-off deferral does not offer "Turn off auto-compact", because that deferral set no switch. — the maintainer asked for it: seeing the early toast while tests are running, the answer is usually "not yet, but do it before the cache goes cold", and the only ways to say that were to dismiss and be asked again or to switch the session to auto-compact permanently. Keeping the one-shot out of `idle_state` is what makes "if the session is updated in the meantime it voids the action" true by construction instead of by cleanup code. This narrows D-20260919-014 (only the toast sets the auto switch) rather than reopening it: the new switch-setting choice is still a click on the toast. (status: active)

- [D-20260921-028] A session whose working directory is inside a `.claude/worktrees/...` checkout is a throwaway spin-off and is refused a queued compaction in code, not only in the server's instructions: `queue_compaction` reads the bound record's `cwd` and answers `queued: false` without writing a request. A desktop scratch workspace under `AppData/Roaming/Claude/scratch-workspaces/` is deliberately out of scope. Those sessions are merged and archived rather than resumed, so the summary is never read; the instructions added in b7db9b1 are advice an agent can miss, and this is the same rule where it cannot. Scratch workspaces are excluded because they are sessions the maintainer talks in, which makes their summaries worth writing - a different kind of throwaway from a worktree. This narrows nothing in D-20260919-012: the tool still acts only on the session that called it, and now sometimes declines to. (status: active)

- [D-20260921-030] ChatGPT Desktop (Codex) is a second platform, read-only by default and never reached through its remote interface. Its state is opened `mode=ro` (`codex_home`), its threads are classified by `thread_source` - `subagent` and `guardian_review` are spin-offs in the sense of D-028 and are refused, failing open on any kind we do not recognise - and its context is measured from the rollout's per-call `usage.total_tokens`, never from a cumulative counter. `platforms` gives both apps one shape for looking; it binds and sends nothing, so D-005 and D-012 stay on each platform's own modules. — the maintainer asked for 1:1 parity with Claude Desktop. Everything except the sending maps: the state store answers what the session records answer, the rollout answers what the transcript answers, and the two guards have exact counterparts (72 of this machine's 105 threads are spin-offs). (status: active)
- [D-20260921-031] A Codex thread is compacted through `thread/compact/start` on an app-server that owns it, and only when no running app holds the thread's writer lock; a held thread is refused, never queued at and never written to. Codex's per-thread lock is the coordination primitive, tested by taking it and giving it back (a byte-range lock is invisible to opening the file). — Measured, not assumed, and it closes three routes rather than one. (1) There is no Stop hook: Codex's hook enum has no turn-end event and its single `notify` slot already holds `codex-computer-use.exe` at a content-hashed path, so turn ends are read from the rollout's `task_started`/`task_complete` instead. (2) `codex queue` is *not* a way in for a compaction, although it is a genuine one for user input - it wrote a real row first try, with no auth and no bridge, so Claude's D-002 classifier problem has no counterpart here. What it cannot carry is a command: `UserInput` has five variants (text, image, localImage, url, fileId) and none is a command, `text_elements` are render spans, and Codex has no `/compact` - its own UI compacts by calling the RPC. (3) The desktop app's app-server is a stdio child of ChatGPT.exe with no socket (the daemon control folder holds none, and `app-server proxy` requires one), so a thread it holds is unreachable from outside, which its own `getStreamRole(threadId).role === "owner"` check states directly. Static analysis confirms this against the live process, not just the daemon folder: the running app-server (a `codex.exe app-server --analytics-default-enabled` child of `ChatGPT.exe`, spawned with no `--listen`) owns zero listening sockets - every connection it holds is an outbound HTTPS to the backend - and the desktop reaches it by writing newline-delimited JSON-RPC to the child's own `stdin` (`this.proc.stdin` in the Electron main), addressed through a virtual `ws://codex-app-server/rpc`; the `--listen unix://` pipe transport exists only in the SSH remote-environment bootstrap. The four local IPC surfaces that do exist were each examined and are not it: the `codex-ipc` pipe is the desktop's own `IpcRouterManager` window-coordination bus (follower/broadcast), the `codex-runner-<hash>-in` pipes are stdin channels to spawned MCP/command sub-runners, and neither carries the `thread/*` methods. A child's stdio is an anonymous pipe held by the parent, so no external process can reach the one channel that speaks `thread/compact/start`. Working with that ownership rule reaches every thread the app is not holding - 27 of this machine's 28 user threads at the time of writing - and refusing the rest is the only safe answer, because writing to a rollout a running app is writing to would corrupt it. (status: active; its observation that Codex has no Stop hook superseded by D-20260924-058: Codex 0.155.1 has one, and a CLI started through `conpact-codex` compacts through it)
- [D-20260921-032] The desktop's Remote Control transport (`wham`) is a fourth closed route to a Codex compaction, closed on authentication rather than on protocol: conPACT never connects to it, and the compaction path stays D-031's `thread/compact/start` on an app-server we own. — Measured, not assumed. The relay wire format is fully legible and is recorded here so it is not re-derived: a segmented base64 byte tunnel, client to server `client_message` / `client_message_chunk` / `ping` / `client_closed` against server to client `ack` / `server_message` / `server_message_chunk` / `pong`, carrying `segment_id`, `segment_count`, `message_size_bytes` and `message_chunk_base64` at a 100KB chunk size and a 1GB maximum message (`app-server-transport/src/transport/remote_control/{segment,websocket}.rs`), and the desktop's `/codex/remote/control/...` endpoints alias the backend's `/wham/remote/control/...`. None of that is the obstacle. The obstacle is that a remote-control *client* is an enrolled device: the socket URL is minted per connection by `getHandshake` against `/codex/remote/control/client` rather than being hardcoded, enrolment runs `POST .../client/enroll/start` for a `device_key_challenge`, mints an OS-backed key (`algorithm`, `protectionClass`, `keyId`) and returns a `device_key_proof` to `.../enroll/finish`, the connect itself carries a proof with `purpose: remote_control_client_websocket`, and the whole flow sits behind a step-up authorisation the user performs in ChatGPT's own settings. Connecting returns `403 Forbidden` at the upgrade, and the three cheap explanations are all eliminated: the token was not stale (194 hours of validity left on it), the header set was not short (retried with the full Codex CLI header set - `chatgpt-account-id`, `originator: codex_cli`, `OpenAI-Beta: responses=experimental`, `User-Agent: CodexCLI/1.0.0` - against the same environment the account's own `GET .../environments` returns 200 for, and it is still 403), and no official tool offers the client role: `codex remote-control` implements only the host side (`start` a daemon offering control, `stop`, `pair` to print a code for a client to consume), so the consuming half lives solely in the desktop and mobile clients. The token is not the credential; an enrolled device is. So "reach the wham socket" means "register conPACT as a permanent device-keyed remote-control client on the user's ChatGPT account" - a standing credential, minted behind an MFA step, which is exactly what D-030's "read-only by default and never reached through its remote interface" rules out, and which would not compact anything the owned app-server cannot already compact. This extends D-20260921-031 rather than reopening it. (status: active)
- [D-20260921-033] Codex's Remote Control is implemented host-side only: conPACT reads what this machine already offers - the enrolment row in Codex's own state store (`mode=ro`, naming only the columns that are not credentials-adjacent) and the shared app-server daemon's liveness - and performs an action only when a command is typed or a button clicked. The actions are the daemon's own (`app-server daemon start|stop|enable-remote-control|disable-remote-control`, `remote-control pair`) plus the three app-server methods with no CLI (`remoteControl/status/read`, `client/list`, `client/revoke`), reached over `app-server proxy` because the control socket is AF_UNIX and Python on Windows cannot open one. Every refusal is an answer with a named reason. — the maintainer asked for parity with Claude's Remote Control, and the relay's two halves are not equally open.
